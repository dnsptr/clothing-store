## 2. Архитектурное решение по интеграции с Т-Банком

### Чек № 1 (Предоплата 100% при оформлении заказа)
1. **Кто фискализирует:** Т-Банк через облачный шлюз АТОЛ Онлайн.
2. **Как настраивается:**
   - Клиент самостоятельно заходит в ЛК Т-Бизнес (*Интернет-эквайринг → Магазины → Онлайн-касса → АТОЛ Онлайн*).
   - Вводит API-данные из файла «Настройки интегратора» (online.atol.ru): login, password, group_code и выбирает **ФФД 1.2**.
   - **Важно:** Разработчикам не требуется доступ к банку-клиенту и не требуется хранить API-пароли АТОЛа на сервере магазина для пробития чека предоплаты.
3. **Что делает бэкенд магазина (Medusa v2):**
   - В запросе `Init` в Т-Банк передается объект `Receipt`:
     - Email / Phone покупателя
     - `Taxation: usn_income`
     - Массив `Items`: наименование, сумма, количество, `Tax: vat105`, `PaymentMethod: full_prepayment`, `PaymentObject: commodity`.
   - При успешной оплате Т-Банк сам отправляет чек в АТОЛ Онлайн.

Подписанный снимок чека v2 включает идентификаторы строк корзины и их количества.
При повторном `Init` и перед подтверждением оплаты он сверяется с текущими
позициями, составом строк и контактом корзины. Неизменная общая сумма и
одинаковое напечатанное наименование товара не разрешают заменить SKU.
Старые снимки v1 намеренно не принимаются для повторного `Init` и
подтверждения: незавершённые оплаты с таким снимком требуют ручной сверки.
Публичный `POST /store/carts/:id/complete` не может создать заказ до
подтверждения платежа: первый заказ создаёт внутренний workflow после
подтверждённого банковского уведомления; публичный запрос допускается только
для уже связанного с корзиной оплаченного заказа.

### Чек № 2 (требование: закрывающий чек и выбытие маркировки; не реализован)

Поскольку обувь и одежда подлежат обязательной маркировке, в момент сборки/отгрузки заказа:
1. Сотрудник склада сканирует код DataMatrix с упаковки.
2. Система отправляет закрывающий чек «Полный расчет» с `Tax: vat5`, `PaymentMethod: full_payment` и кодом маркировки (тег 1163 / объект `MarkCode` типа GS1M).
3. **Канал отправки:** Через API Т-Банка `/cashbox/SendClosingReceipt` (используя имеющиеся TerminalKey и Password) либо через прямой REST API АТОЛ Онлайн.
4. ОФД «Такском» автоматически передает код выбытия в систему «Честный ЗНАК».

### Возврат предоплаты (автоматизация заблокирована)

Т-Банк использует `Cancel` и для отмены до захвата, и для возврата после
захвата. Между `GetState` и `Cancel` возможен захват, поэтому backend **не
вызывает `Cancel` автоматически** ни для активной сессии, ни при полном или
частичном возврате. `refundPayment` завершается отказом до обращения в банк.
Нет подтверждённой физической приёмки товара, прав сотрудника и возвратного
чека на уровне этого API. Уже терминальные отменённые сессии можно очистить
после чтения `GetState`; активные требуют ручной проверки. Правила банка:
[отмена и возврат платежа](https://developer.tbank.ru/eacq/scenarios/cancel_confirm/).

Подписанные фискальные уведомления журналируются отдельно и дубли подавляются
в PostgreSQL. Фискальный журнал виден только авторизованному администратору;
свободный текст `ErrorMessage` не сохраняется. Запись callback **не доказывает**
фактический чек АТОЛ/ОФД и не отправляет закрывающий или возвратный чек.
