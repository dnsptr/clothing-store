## Предпросмотр без покупки

Заказчик разрешил показывать карточки до получения остатков, дат изготовления и ссылок на реестр. У товаров установлено `metadata.storefront_preview: true`.

- На витрине отображается «Скоро в продаже», покупка отключена.
- Backend проверяет товары в hooks создания корзины, добавления позиции и завершения корзины. Запрос напрямую к API также не разрешает покупку.
- Учёт остатков включён, предзаказ запрещён. Остатки не выдумывались и не заполнялись.
- В предпросмотре допустимы только два незаполненных поля профиля: дата изготовления и ссылка на реестр. Остальные правила публикации сохраняются.
- В редакторе карточки есть переключатель предпросмотра. При его отключении полный профиль снова обязателен.
- Снятые с публикации товары также блокируются при добавлении и завершении корзины.

Для начала продаж нужны реальные остатки, даты изготовления и ссылки на реестр. Следует также сверить адреса изготовителя и исправления цветовых названий с заказчиком. Фото ярлыков и обмеры пока не предоставлены.

## Повторение импорта

Версионируемые данные: `src/scripts/data/customer-catalog.ts` и `customer-physical.json` внутри backend. При обновлении источника сначала сверить эти данные с Excel.

После распаковки архива:

```powershell
node scripts/prepare-customer-media.mjs ".env-catalog-media/каталог фото"
```

Загрузить содержимое `optimized` в каталог медиа на сервере и убедиться, что URL доступны. Заглушка должна находиться там же под именем `placeholder.webp`.

Проверка плана без записи:

```powershell
node --env-file=.env.server-admin.local scripts/sync-customer-catalog.mjs
```

Обновление карточек с сохранением текущего статуса:

```powershell
node --env-file=.env.server-admin.local scripts/sync-customer-catalog.mjs --apply
```

Первичная публикация предпросмотра и замена демовитрины:

```powershell
node --env-file=.env.server-admin.local scripts/sync-customer-catalog.mjs --apply --publish-previews --archive-demo --home
```

Повторный импорт предназначен для этой поставки: он перезаписывает её фото, характеристики, связи, цены и включает предпросмотр. Не запускать после ручного редактирования карточек без проверки различий. Остатки, существующие SKU и идентификаторы вариантов сохраняются. Новые варианты добавляются без фиктивных запасов.

## Развёртывание

Текущий рабочий платёжный образ сохранён как основа `mm-backend-candidate:d8836f0a`. Каталожный релиз `mm-backend-catalog:20261107` добавляет только валидатор карточки, проверку качества, вспомогательные функции, hooks запрета покупки и собранную админку. Модули оплаты и доставки из основной ветки не подменяются.

```powershell
npm run backend:build
node scripts/prepare-catalog-overlay.mjs
```

Содержимое `.env-catalog-release` и `apps/backend/Dockerfile.catalog-overlay` используется как build context. На сервере активен `compose.production.yml` вместе с `compose.candidate.yml`.

Архив релиза: `/opt/mario-mikke-releases/catalog-20261107/`.
Конфигурация для отката: `medusa-prototype/backups/compose.pre-catalog-20261107.yml` на сервере. Откат образа не откатывает данные каталога. Перед восстановлением дампа учитывать заказы и прочие изменения, сделанные после него.

Подборки для главной, меню и страниц коллекций пока описаны в `src/lib/collections.ts`. Карточки категорий, материалы и hero редактируются через контент главной в Medusa.
