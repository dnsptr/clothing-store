# Каталог с фотографиями: 7 ноября 2026

## Текущий режим продаж

После первоначального предпросмотра владелец разрешил покупки до подключения 1С. У 21 товара отключён `storefront_preview`, у 159 вариантов установлен `manage_inventory: false`, `allow_backorder: false`. Настоящие складские количества не заполнялись. В metadata записан временный режим `catalog_inventory_mode: untracked_until_1c`.

Наличие каждого цвета проверяется вручную. Автоматического ограничения заказанного количества сейчас нет. При интеграции 1С необходимо загрузить реальные остатки и связи вариантов со складами, включить `manage_inventory` и убрать временную метку режима. Существующие цвета, SKU, идентификаторы вариантов, цены и фотографии сохранены.

Пустые поля профиля больше не блокируют публикацию. Проверка качества продолжает показывать их как незаполненные; заполненные даты и ссылки проверяются на формат. Название, фото, категория, варианты и положительные рублёвые цены по-прежнему обязательны. Переключатель предпросмотра остаётся доступен для намеренного запрета покупки отдельных товаров.

Операция открытия текущего каталога выполняется отдельным скриптом с dry-run по умолчанию:

```powershell
node --env-file=.env.server-admin.local scripts/open-customer-sales.mjs
node --env-file=.env.server-admin.local scripts/open-customer-sales.mjs --apply
```

Скрипт не создаёт товары и не заполняет количества. Перед записью сохраняет снимок прежних значений, после записи проверяет сохранность цен, SKU и идентификаторов вариантов. Данные до переключения сохранены также в `backups/pre-open-sales_20261107_141911.dump.gz` и соответствующем архиве медиа на сервере и локально.

Активный образ этого этапа: `mm-backend-catalog:20261107-sales`. Его изменения ограничены правилами каталога и админкой; основа платёжного образа прежняя.

Проверки этапа: 23 целевых unit-теста backend, 29 тестов витрины и кабинета, сборка Medusa и админки. На публичном сайте проверены добавление и удаление товара в корзине на desktop/mobile. Заказы и платежи в этой проверке не создавались. Конфигурация отката серверного образа сохранена в `backups/compose.pre-open-sales-20261107.yml`; возврат образа сам по себе не возвращает флаги товаров и вариантов.

## Первоначальный предпросмотр без покупки

При первом импорте заказчик разрешил показывать карточки до получения остатков, дат изготовления и ссылок на реестр. Тогда у товаров был установлен `metadata.storefront_preview: true`. Этот режим впоследствии отключён, см. текущий режим продаж выше.

- На витрине отображается «Скоро в продаже», покупка отключена.
- Backend проверяет товары в hooks создания корзины, добавления позиции и завершения корзины. Запрос напрямую к API также не разрешает покупку.
- Учёт остатков включён, предзаказ запрещён. Остатки не выдумывались и не заполнялись.
- Первоначально в предпросмотре допускались только два незаполненных поля профиля: дата изготовления и ссылка на реестр. Текущие правила разрешают пустые дополнительные сведения независимо от предпросмотра.
- В редакторе карточки есть переключатель предпросмотра. Он управляет запретом покупки, а не обязательностью дополнительных сведений.
- Снятые с публикации товары также блокируются при добавлении и завершении корзины.

Даты изготовления и ссылки на реестр пока отсутствуют. Следует также сверить адреса изготовителя и исправления цветовых названий с заказчиком. Фото ярлыков и обмеры пока не предоставлены.

## Повторение импорта

Версионируемые данные: `src/scripts/data/customer-catalog.ts` и `customer-physical.json` внутри backend. При обновлении источника сначала сверить эти данные с Excel.

После распаковки архива:

```powershell
node scripts/prepare-customer-media.mjs ".env-catalog-media/каталог фото"
```

Загрузить содержимое `optimized` в каталог медиа на сервере и убедиться, что URL доступны. Заглушка должна находиться там же под именем `placeholder.webp`.

Проверка плана без записи:

```powershell
node --env-file=.env.server-admin.local scripts/sync-customer-catalog.mjs
```

Обновление карточек с сохранением текущего статуса:

```powershell
node --env-file=.env.server-admin.local scripts/sync-customer-catalog.mjs --apply
```

Первичная публикация предпросмотра и замена демовитрины:

```powershell
node --env-file=.env.server-admin.local scripts/sync-customer-catalog.mjs --apply --publish-previews --archive-demo --home
```

Повторный импорт предназначен для этой поставки: он перезаписывает её фото, характеристики, связи и цены. Обычный `--apply` сохраняет действующий предпросмотр и режим учёта остатков; явный `--publish-previews` возвращает предпросмотр и учёт остатков. Не запускать после ручного редактирования карточек без проверки различий. Существующие SKU и идентификаторы вариантов сохраняются. Новые варианты добавляются без фиктивных запасов.

## Развёртывание

Текущий рабочий платёжный образ сохранён как основа `mm-backend-candidate:d8836f0a`. Каталожные релизы добавляют только валидатор карточки, проверку качества, вспомогательные функции, hooks запрета покупки и собранную админку. Модули оплаты и доставки из основной ветки не подменяются.

```powershell
npm run backend:build
node scripts/prepare-catalog-overlay.mjs
```

Содержимое `.env-catalog-release` и `apps/backend/Dockerfile.catalog-overlay` используется как build context. На сервере активен `compose.production.yml` вместе с `compose.candidate.yml`.

Архив релиза: `/opt/mario-mikke-releases/catalog-20261107/`.
Конфигурация для отката: `medusa-prototype/backups/compose.pre-catalog-20261107.yml` на сервере. Откат образа не откатывает данные каталога. Перед восстановлением дампа учитывать заказы и прочие изменения, сделанные после него.

Подборки для главной, меню и страниц коллекций пока описаны в `src/lib/collections.ts`. Карточки категорий, материалы и hero редактируются через контент главной в Medusa.
