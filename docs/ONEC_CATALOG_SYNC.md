# Применение каталога 1С: цены и варианты

## Результат пилота 24.11.2026

На сервере применён товар **1916**: 8 вариантов обновлены на месте, 3 созданы,
все 11 связаны с отдельными ID предложений 1С, цена каждого — **5 500 ₽**.
Повторный серверный расчёт: `create=0`, `update=0`, `untouched=0`.
Проверена цена при добавлении в тестовую корзину; позиция затем удалена,
заказ и оплата не создавались. Сохранность медиа, описания, категорий, старых
ID/SKU и настроек учёта запасов проверена сравнением снимков. Остальные
32 карточки не изменились. Резервная копия PostgreSQL хранится на сервере.

Исходный план оставшихся 20 товаров содержал 85 новых вариантов, 136 обновлений
и 15 старых вариантов без соответствия. После [разбора этих вариантов](ONEC_LEGACY_VARIANTS_REVIEW.md)
добавлены 14 точечных привязок, без глобальных правил объединения цветов.

## Массовое применение 24.11.2026

Остальные **20 товаров обновлены на сервере**: 71 вариант создан, 150 обновлены
на месте. Вместе с пилотом синхронизированы цены и связи **21 товара / 232
характеристик 1С**. Все 232 цены проверены через Store API. Повторный расчёт
массового пакета: `create=0`, `update=0`, `untouched=1`.

Единственный оставленный без привязки вариант — `MM-1351-OS-15`, «тёмно шоколадный».
Он не объединён с двумя ID «шоколадный» по явному решению владельца проекта;
его прежняя цена и настройки доступности сохранены. Не считать его синхронизированным.

Сохранность прежних ID, SKU, подписей, настроек учёта запасов, изображений,
описаний, категорий и коллекций проверена сравнением снимков. Пилот 1916 и
12 остальных карточек вне этого применения не изменились. Проверена цена в
тестовой корзине для одного из четырёх подтверждённых соответствий с обратным
порядком цветов; позиция удалена, заказ, оплата и доставка не создавались.
Перед массовым применением сохранена новая проверенная копия PostgreSQL на сервере.

Запись остатков и автоматическое применение HTTP-обмена по-прежнему выключены.
Новые варианты недоступны для покупки до этапа импорта запасов; существующий
ручной режим старых вариантов не менялся.

## Команда

Команда `src/scripts/sync-onec-catalog.ts` выполняется оператором через
`medusa exec`. В собранном backend используется файл `.js`. По умолчанию
команда **только рассчитывает план**. Приём XML по HTTP по-прежнему не
применяет изменения автоматически; расписание обмена на запись не включено.

## Границы этапа

- Только существующие товары согласованного списка 21 артикула.
- Связи товаров и вариантов сохраняются по ID каталога, товара и предложения 1С.
- Цены вариантов берутся из 1С; цена родительской записи не наследуется.
- Совпавшие существующие варианты сохраняют ID, SKU и отображаемые подписи.
- Новые варианты получают устойчивый SKU на основе ID 1С. Одинаковые цвета
  различаются подписью «вариант 2» и далее; их ID и остатки не объединяются.
- Новые значения опций создаются и связываются с конкретным товаром через
  `setProductProductOptionsWorkflow` (отдельная привязка нужна в Medusa 2.22).
- Фотографии, описания, состав, категории, коллекции и статус публикации не меняются.
- Непривязанные старые варианты не удаляются и не отключаются автоматически.
  Перед массовым применением их нужно проверить отдельно: они могут оставаться
  доступными в прежнем ручном режиме и не являются подтверждённым наличием 1С.
- У существующих вариантов не меняются флаги учёта запасов и уровни остатков.
  Новые варианты создаются с учётом запасов и без предзаказа: до этапа импорта
  остатков они недоступны для покупки. Автоматически создаются лишь их штатные
  записи учёта, без заполнения уровней запасов.
- Заказы, оплата, доставка, резервы и чеки не затрагиваются.

## Параметры команды

| Переменная | Назначение |
| --- | --- |
| `ONEC_SYNC_ARTICLES` | Обязательный явный список артикулов через запятую, для пилота `1916` |
| `ONEC_SYNC_CATALOG_SESSION` | ID сеанса проверенного каталога |
| `ONEC_SYNC_CATALOG_FILE` | Имя XML каталога, по умолчанию `import.xml` |
| `ONEC_SYNC_OFFERS_SESSION` | ID сеанса проверенных предложений |
| `ONEC_SYNC_OFFERS_FILE` | Имя XML предложений, по умолчанию `offers.xml` |
| `ONEC_SYNC_APPLY` | Только точное значение `true` разрешает запись |
| `ONEC_SYNC_EXPECTED_PLAN_SHA256` | Контрольная сумма одобренного плана из `ONEC_SYNC_PLAN` |
| `ONEC_SYNC_BACKUP_FILE` | Путь к проверенной резервной копии PostgreSQL внутри `ONEC_EXCHANGE_STORAGE_DIR/.sync/backups/` |

Учётные данные обмена используются из существующего окружения backend.
Не передавайте секреты через аргументы команд и не коммитьте дампы или планы.

## Порядок запуска

1. Проверить полный пакет XML в журнале, зафиксировать снимок каталога.
2. Сделать `pg_dump -Fc` и проверить архив командой `pg_restore --list`.
   Копия остаётся на сервере в закрытом каталоге, не скачивается в репозиторий.
3. Выполнить команду без `ONEC_SYNC_APPLY`, изучить счётчики и план.
4. Передать контрольную сумму этого плана, путь резервной копии и
   `ONEC_SYNC_APPLY=true`. Если каталог, источники или план изменились,
   применение будет отклонено до вызова изменяющих workflows.
5. Проверить данные товара и корзину, затем снова рассчитать план. Для
   того же пакета ожидается `create=0`, `update=0`, без изменений опций.

Планы и результаты (`planned`, `applied`, `failed`) сохраняются с правами `0600`
в приватной папке `.sync` внутри хранилища обмена. Она не публикуется через HTTP.
Одновременные применения сериализованы отдельной блокировкой; зависшую
блокировку после аварии нельзя удалять, пока не проверен процесс и результат.

Проверка совместимости цен консервативная: валюты кроме RUB, несколько базовых
цен и цены с условиями не перезаписываются этим этапом. Конфликтующие связи,
смена измерений привязанной характеристики и устаревшие экспорты требуют проверки.
Процесс может остановиться между товарами; повторный расчёт использует уже
сохранённые связи и не должен повторно создавать варианты.
