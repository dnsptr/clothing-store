# Редактор товаров

## Область изменений

Расширения каталога и витрины. Оплата, доставка, остатки, интеграции 1С и секреты не изменены. Для публикации расширений потребуется отдельный деплой backend и фронтенда; миграций БД нет.

В меню Medusa добавлен «Редактор товаров» (`/app/catalog-editor`). Такой же редактор доступен виджетом на стандартной странице товара. Штатный каталог Medusa остаётся единственным источником идентификаторов, вариантов, SKU, цен и связей.

## Все 17 пунктов

| Пункт | Где заполняется / хранится |
| --- | --- |
| 1. Наименование | Стандартный `product.title` |
| 2. Модель / артикул | `metadata.catalog_profile.model`, отдельно от SKU варианта |
| 3. Цена | Стандартные цены вариантов Medusa; рубли, не копейки |
| 4. Цвет | Стандартная опция «Цвет» |
| 5. Размеры | Стандартная опция «Размер»; при создании OS / One Size нормализуются в ONE SIZE |
| 6. Состав | `composition` |
| 7. Подкладка | `lining` либо явная отметка `no_lining` |
| 8. Страна | `country` |
| 9. Изготовитель | `manufacturer` |
| 10. Адрес изготовителя | `manufacturer_address` |
| 11. Дата изготовления | `manufactured_at`, ММ.ГГГГ |
| 12. Уход | `care` |
| 13. Бренд | `brand` |
| 14. Документ о соответствии | `conformity_document` |
| 15. Реестр | `registry_url`, только HTTPS |
| 16. Фото товара | Стандартные `images` и `thumbnail` |
| 17. Фото ярлыков | `metadata.catalog_profile.label_images`, отдельный публичный блок |

Все дополнительные текстовые поля находятся в `metadata.catalog_profile`. Фото ярлыков публичны по подтверждённому решению пользователя. Они не смешиваются с основной галереей. Нового приватного хранилища нет.

Дата изготовления пока описывает представленное изделие/партию. Если один товар продаётся из нескольких партий с разными датами, потребуется отдельная модель партий; нельзя молча перезаписывать её как общую дату всех единиц.

## Процесс

1. Создать черновик. Можно указать только название; вымышленные значения вместо недостающих характеристик не подставляются.
2. При необходимости задать первый вариант: отдельный SKU, цвет, размер и цену. Остальные варианты и изменения цен выполняются штатными формами Medusa по ссылке на вкладке «Варианты и цены».
3. Заполнить характеристики, фотографии и связи. Первый кадр основной галереи становится главным; порядок меняется стрелками.
4. Сохранить черновик или опубликовать после заполнения обязательных полей. Сохранение опубликованного товара черновиком снимает его с витрины.

При создании используется канал продаж магазина по умолчанию, если он настроен. Новый вариант имеет включённый учёт остатков и запрещённую продажу без остатка. Сам остаток редактор не устанавливает; публикация не означает доступность к покупке.

Проверка публикации выполняется и в редакторе, и на стандартных POST-маршрутах создания/обновления продукта. Обычные изменения старых карточек без профиля сохраняют совместимость. Явная публикация требует заполненного профиля. Это не глобальный hook на все внутренние workflows: сторонние импорты и будущая 1С должны отдельно соблюдать тот же контракт.

Фото ярлыков сейчас являются предупреждением, а не блокирующим условием. Обязательность полей является техническим правилом редактора, не юридическим заключением. Все фотографии принимаются в JPEG/PNG/WebP до 10 МБ; галерея до 20 файлов, ярлыки до 6. Файлы загружаются сразу, привязка к товару сохраняется кнопкой сохранения. Удаление из карточки не удаляет физический файл: он может использоваться другими товарами. Автоматическая уборка непривязанных файлов пока не реализована.

Редактор проверяет `updated_at` перед сохранением, чтобы предупредить об уже замеченных изменениях другого сотрудника. Это не транзакционный compare-and-swap; одновременное сохранение в одну миллисекунду требует серверного механизма версий в следующем этапе.

## Витрина и метрики

Непустые характеристики выводятся на странице товара, ссылка на реестр открывается отдельно. Фото этикеток доступны раскрываемым блоком.

Каталог получает категории и коллекции Medusa. Ссылка на коллекцию: `/catalog?collection=<Medusa collection ID>`. Старые `/collection/...` с образами остаются отдельным редакционным разделом и не подменяются коллекциями Medusa. Меню главной и хедера в этом этапе полностью не переводились на динамический каталог.

Вкладка «Метрики» предусмотрена, но пока показывает отсутствие подключения. Это согласовано с пользователем: счётчик ещё не создан. Нет сбора данных, фиктивных продаж или нулевых счётчиков вместо неизвестных значений.

## Проверка перед деплоем

- Создать черновик без характеристик и убедиться, что он не доступен покупателю.
- Заполнить все поля на тестовом товаре; проверить вёрстку длинного адреса и состава, основной галереи и ярлыков на телефоне.
- Проверить сохранение существующей карточки без изменения SKU, ID вариантов, цен и остатков.
- Проверить отказ публикации неполной карточки через стандартную админку.
- Проверить категории, коллекцию, канал продаж и доступность при реальном остатке.
- Проверить карточку со вторым размером через штатное управление вариантами.
