# Футер и документы

Редактор: `https://api.mariomikke.shop/app/site-documents`.
Также доступен из раздела «Контент» административной панели.

## Порядок работы

1. Выберите страницу во вкладке «Документы и страницы».
2. Измените заголовок, описание, разделы, абзацы, списки и примечания.
3. При необходимости загрузите PDF/DOCX до 10 МБ или укажите ссылку на файл.
4. Во вкладке «Футер» отредактируйте колонки меню, ссылки, контакты и подпись.
5. Нажмите «Сохранить черновик» и проверьте вкладку «Предпросмотр».
6. Нажмите «Опубликовать» только после согласования текста.

Сохранение черновика не меняет сайт. Публикация применяется сразу ко всем
страницам и футеру вместе. Посетитель увидит новую редакцию при обычном
обновлении страницы; принудительная очистка кэша не требуется.

## Ограничения

- Семь обязательных правовых страниц и ссылки на них защищены от удаления.
  Подписи ссылок и их порядок менять можно.
- Дополнительные информационные страницы можно добавлять и удалять.
  Перед удалением нужно убрать ведущие на них ссылки из меню.
- PDF/DOCX заменяется файлом целиком, а не редактируется внутри браузера.
- Загруженные файлы используют публичное хранилище медиа магазина.
  Не загружайте персональные данные, внутренние документы и секреты.
  Черновик защищает текст редакции, но не делает загруженный файл приватным.
- Удаление ссылки не удаляет файл из хранилища.
- Изменение контактов в футере не заменяет их автоматически в тексте
  документов и приложенных файлах: проверьте эти места отдельно.
- Редактор не выполняет юридическую проверку и не снимает примечания
  о предварительной редакции автоматически.

## Версии и безопасность

Сохраняются текущая публикация и десять предыдущих. Восстановление переносит
выбранную редакцию только в черновик. Для изменения сайта нужна отдельная
публикация. Одновременная запись со старой ревизией отклоняется: обновите
редактор и перенесите изменения в актуальную версию.

Доступ требует авторизации сотрудника и прав чтения/изменения магазина.
Публичный API возвращает только опубликованный контент, без черновиков,
истории, идентификаторов сотрудников и прочих метаданных магазина.

## Технически

Данные хранятся в `Store.metadata.site_content_editor`, обновляются штатным
workflow Medusa под блокировкой. Миграции базы не требуются.
До первой публикации витрина использует прежние тексты и ссылки из репозитория.
Установка редактора сама по себе ничего не публикует.

После изменения исходных статических текстов разработчиком выполните
`node scripts/export-site-content-defaults.mjs`. Проверка актуальности входит
в `npm run test:content`. Уже сохранённые редакции этим не заменяются.

Общий контракт находится в `src/lib/site-content-contract.ts`. Этот же скрипт
копирует его в бэкенд, чтобы обе сборки оставались независимыми.
Копию `medusa-prototype/apps/backend/src/lib/site-content-contract.ts`
вручную не редактируйте. Исходники бэкенда остаются исключены из загрузки Vercel.

Отложенная проверка резервов 1С: [контрольная точка](ONEC_STOCK_CHECKPOINT.md).
