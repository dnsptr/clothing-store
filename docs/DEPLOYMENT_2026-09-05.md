## Подключение витрины

Локальная `.env.local` обновлена. Новые публичные значения отдельно сохранены
в `.env.server-storefront.local` в корне проекта, файл исключён из Git.
Backend разрешает Store/Auth запросы с `https://www.mariomikke.shop` и
`http://localhost:3000`; админка работает на домене API.

В Vercel нужно обновить переменные соответствующего проекта:

- `NEXT_PUBLIC_MEDUSA_PUBLISHABLE_KEY` и `NEXT_PUBLIC_MEDUSA_REGION_ID`.
- `MEDUSA_PUBLISHABLE_KEY` и `MEDUSA_REGION_ID`, если используются серверные
  переопределения. Они не должны указывать на старую базу.
- Оба URL backend должны указывать на `https://api.mariomikke.shop`.
- Режим данных должен оставаться `medusa`.

Значения взять из `.env.server-storefront.local`. Затем выполнить Redeploy:
`NEXT_PUBLIC_*` встраиваются в клиентскую сборку. В исходном деплое 5 сентября
Vercel не обновляли; текущие переменные Vercel 26 сентября не проверены.

Старые идентификаторы товаров, корзин и регионов больше не существуют в новой
базе. При проверке использовать новую корзину; ранее сохранённые корзины и
избранное нельзя считать восстановленными.

## Ручной разбор опросов GetState (после отдельного деплоя)

- Medusa admin `/app/tbank-poll-review` показывает попытки в `manual_review`,
  статус сессии и историю действий; банковские секреты и полные данные
  платёжной сессии API не возвращает. Эту страницу и API нельзя считать
  доступными на работающем сервере до применения новой миграции и образа.
- `Повторить проверку` сбрасывает счётчик ошибок и даёт старой попытке
  ограниченное часовое окно для повторного `GetState`. Действие фиксирует
  авторизованного сотрудника и причину; новый заказ вручную не создаётся.
  Повтор допустим только при активном исходном терминале: при смене/отключении
  терминала случай остаётся на ручной проверке, а не исчезает из очереди.
  Если открытая карточка устарела (случай повторно попал на проверку) или другое
  действие уже выполнено, API отвечает `409`; обновите карточку перед решением.
- `Проверить и завершить` допустимо только при свежем `GetState=CONFIRMED`
  с совпадающими реквизитами и уже захваченном платеже, связанном с
  существующим заказом. Ошибка банка, отсутствие заказа или конкурирующее
  действие оставляют попытку на ручной проверке; принудительного закрытия нет.
- Минутная задача заявляет неотправленные события с fenced lease и передаёт
  сотрудникам Telegram-сообщение с ключом идемпотентности на переход в
  `manual_review`. `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID` нужны оба:
  без них событие остаётся в БД, но **никого не уведомляет**. Переменные
  передаются в контейнер новым Compose только после его деплоя; проверка
  доставки реального сообщения обязательна до включения продаж.
